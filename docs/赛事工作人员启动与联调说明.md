# RMTC 参赛程序 · 工作人员启动说明

## 1. 包信息

| 项 | 内容 |
|---|---|
| ROS 包名 | `rmtc_bot` |
| 构建类型 | `ament_python` |
| 提交根目录 / 构建工作区 | `rmtc_bot/` |
| 源码根目录 | `rmtc_bot/src/rmtc_bot` |
| 主程序 | `src/rmtc_bot/rmtc_bot/main.py` |
| 入口点 | `rmtc_bot = rmtc_bot.main:main` |
| 启动文件 | `src/rmtc_bot/launch/contestant.launch.py` |
| 现场配置文件 | `src/rmtc_bot/config/decision_config.json`（只允许改 `decision_type`） |

## 3. 构建

在提交根目录构建：

```bash
cd rmtc_bot
source /opt/ros/humble/setup.bash
colcon build --packages-select rmtc_bot
source install/setup.bash
```

产物在 `rmtc_bot/install/`，配置副本在 `install/rmtc_bot/share/rmtc_bot/config/decision_config.json`。

依赖：ROS 2 Humble、`rclpy`、`std_msgs`、Python `requests`。跨机联调建议 `RMW_IMPLEMENTATION=rmw_fastrtps_cpp`。

## 4. 启动参数

接入信息通过 launch 参数传入，不需要提前 `export` 环境变量。

| 参数 | 必填 | 说明 |
|---|---|---|
| `seat` | 是 | `A`/`B`/`C`/`D` |
| `team_name` | 是 | 队伍显示名，UTF-8 1–96 字节 |
| `ros_domain_id` | 是 | 与裁判机一致；由 launch 写入 `ROS_DOMAIN_ID` 环境 |
| `gateway` | 阶段二 | AI 网关基址，如 `http://<裁判机IP>:8000`；练习裁判为 `http://127.0.0.1:8080` |
| `team_token` | 阶段二 | 本场席位令牌；为空时程序可运行但 LLM 关闭 |

其余可选参数（`model`、`max_tokens`、`llm_quota`、`fort_*`）一般不用传，使用默认值即可。

- `llm_quota` 默认 `100`，与「500 Tick 内最多 100 次 LLM 调用」一致，**不要调大**；代码按实际 HTTP 调用计数（含重试与失败请求），达到上限即降级。
- `fort_auto_center` 默认 `1`：按感知的实际地图尺寸把堡垒标定到地图中心 3×3，换轮次地图（20×20 / 24×24）无需改参数。若公告给出固定坐标，再传 `fort_auto_center:=0` 与 `fort_x0..fort_y1`。

取值优先级：**launch 参数 > 同名环境变量 > 内置默认**。未显式传参时回退 `RMTC_SEAT` 等环境变量；正式比赛建议显式传参，避免 shell 中残留上一场的值。

## 5. 启动

```bash
cd rmtc_bot
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch rmtc_bot contestant.launch.py \
    seat:=A team_name:=星火队 \
    gateway:=http://<裁判机IP>:8000 team_token:=<本场令牌> \
    ros_domain_id:=<赛前公布值>
```

等价方式：

```bash
./src/rmtc_bot/scripts/run_contestant.sh seat:=A team_name:=星火队 \
    gateway:=http://<裁判机IP>:8000 team_token:=<本场令牌> ros_domain_id:=27

ros2 run rmtc_bot rmtc_bot --ros-args -p seat:=A -p team_name:=星火队
```

启动日志应依次出现 `配置就绪`、`RosBridge 就绪`、`LLM 网关启用`（无令牌时无此行）、`RMTC bot 节点就绪`。`配置就绪` 行的 `seat`、`domain`、`gateway` 应与命令一致。

启动后可快速确认：

```bash
ros2 node list | grep rmtc_bot      # 节点存在
ros2 topic list | grep team_A       # 话题按席位创建
ros2 param list /rmtc_bot_node      # 参数已声明
```

停止：前台 `Ctrl+C`；后台按 PID `kill`，先 `pgrep -af rmtc_bot` 确认，不要用宽匹配的 `pkill -f`。

## 6. 轮间与上场规则

- **决策类型只在每轮之间的 10 分钟整备时间修改**，且只能改 `decision_type`，不得修改源码、提示词或算法参数。
- 推荐做法：把 `src/rmtc_bot/config/decision_config.json` 复制到工作区根 `rmtc_bot/`，只改其中的 `decision_type`。程序启动时优先读取当前目录的 `decision_config.json`，**无需重新构建**；该文件已加入 `.gitignore`，不污染 git 状态。
- 每轮地图公示后，堡垒位置由 `fort_auto_center` 按实际地图尺寸自动居中，一般不需要额外参数；只有公告给出固定坐标时才关闭自动居中并显式传 `fort_x0..fort_y1`。
- **上场前执行 `git status` 并向工作人员出示**：源码目录必须干净；构建产物（`build/ install/ log/`）和轮间临时 `decision_config.json` 已被忽略，正常应显示 `nothing to commit, working tree clean`。
- 每场之间准备时间严格 3 分钟：提前把启动命令写好，只替换席位、令牌、域号等参数，避免现场构建或排查。
- LLM 配额为 **100 次 / 500 Tick**，程序默认 `llm_quota=100` 并硬性截断；任务公告不占用配额，配额全部留给随机事件。
- 双赛场的令牌与分组以赛事当天公共文档为准；两台赛场各自使用对应席位与令牌启动，互不混用。

## 7. 其他注意事项

- 换场只改启动命令中的参数和 `decision_type`，不改代码、不重启 shell 也不需要清理环境变量。
- 令牌只出现在启动命令中，不写进脚本、文档或截图；赛后清理终端历史。
- 同一席位同一时间只允许一个控制进程。
- 比赛期间不得接近裁判；确需沟通请联系台下工作人员转达。
